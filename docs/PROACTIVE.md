# Proactive 모드 설계 메모 (Design note)

> **상태: 열린 질문 (Open question).** v0.1에는 구현하지 않았습니다. 아래는 검토용 메모입니다.

## 아이디어

팀원이 먼저 요청하지 않아도, 작업 스타일을 지켜보다가 "이런 Skill을 만들면 좋겠어요"라고
먼저 **제안**하거나, 동의를 받아 **만들어 주는** 모드입니다.

## 가능한 구현 방향 (검토 전)

| 단계 | 방법 | 비고 |
| --- | --- | --- |
| 1. 관찰 | `UserPromptSubmit` 또는 `Stop` hook이 요청의 **종류만** 짧게 기록 | 원문이 아닌 요약 태그만 저장 |
| 2. 저장 | 플러그인 데이터 폴더 `${CLAUDE_PLUGIN_DATA}`에 로컬 저장 | 업데이트해도 유지되고, 각자 PC에만 남음 |
| 3. 감지 | 같은 종류의 요청이 일정 횟수 이상 반복되면 후보로 표시 | 기준 횟수는 미정 |
| 4. 제안 | `SessionStart` hook이 다음 세션 시작 때 한 줄로 제안 | 제안만 하고, 만들기는 사용자가 동의할 때만 |
| 5. 생성 | 동의하면 `forge-intake`로 이어서 진행 | 기존 흐름 재사용 |

## 확인해야 할 것

- [ ] **개인정보·보안:** 무엇을 기록해도 되는지, 회사 정책상 허용 범위
- [ ] **동의:** 관찰을 켜고 끄는 방법 (기본값은 꺼짐을 권장)
- [ ] **정확도:** 반복 업무를 어떻게 같은 종류로 묶을지, 오탐을 어떻게 줄일지
- [ ] **피로도:** 제안 빈도 상한 (예: 하루 한 번)
- [ ] **기술 검증:** hook이 받는 이벤트 정보로 충분한지 실제 테스트 필요
