# PRD: 데모POS 모바일 주문 연동 (픽업 주문 수신)

| 항목 | 내용 |
| --- | --- |
| 문서 ID | PRD-26-020 |
| 작성자 | 최유진 (POS기획) |
| 이해관계자 | POS개발파트 박지훈·이서윤, 운영지원 한상우, 가맹점 대표 자문단 3명 |
| 상태 | 초안 |
| 최종 수정 | 2026-05-07 |

## 1. 배경 / 문제
- 카페 가맹점의 앱 픽업 주문 비중이 전체 주문의 27%까지 늘었으나, 픽업 주문은 별도 태블릿으로 수신해 POS에 다시 입력하고 있음
- 이중 입력으로 피크타임 주문당 평균 40초가 추가되고, 월 평균 매장당 6건의 입력 오류(메뉴·옵션 누락) 발생
- 가맹점 설문(52개점) 중 81%가 "태블릿 하나로 통합"을 1순위 개선 요청으로 선택

## 2. 목표와 비목표
### 목표
- 앱 픽업 주문을 POS에서 바로 수신·접수·완료 처리한다
- 픽업 주문 입력 오류를 매장당 월 1건 이하로 줄인다

### 비목표
- 배달앱(외부 플랫폼) 주문 연동은 이번 범위에 포함하지 않는다
- 주방 디스플레이(KDS) 연동은 별도 과제
- 픽업 주문 결제는 앱에서 완료되므로 POS 결제 흐름은 변경하지 않는다

## 3. 사용자 스토리
| ID | 사용자 | 스토리 |
| --- | --- | --- |
| US-01 | 캐셔 | 새 픽업 주문이 들어오면 판매 중에도 알림을 보고 바로 접수하고 싶다 |
| US-02 | 캐셔 | 재료 소진 메뉴가 있으면 주문을 거절하고 사유를 고객에게 보내고 싶다 |
| US-03 | 점장 | 픽업 주문 매출이 일반 매출과 함께 정산에 잡히길 원한다 |

| --- | --- | --- | --- |

| REQ-02 | 주문 접수/거절, 거절 사유 선택(재료 소진/영업 종료/기타) | P0 | US-01, US-02 |

| REQ-04 | 픽업 주문 목록 (신규/준비중/픽업대기/완료 탭) | P0 | US-01 |

## 5. 수용 기준
- REQ-01: 판매 화면에서 결제 중이어도 알림 배너가 노출되며, 결제 흐름을 막지 않는다
- REQ-02: 거절 시 고객 앱에 사유가 10초 이내 전달되고 앱 결제는 자동 취소된다
- REQ-06: 정산 화면에 "픽업 주문" 행이 생기고 합계는 기존 매출 합계에 포함된다
- 네트워크 끊김 시 신규 주문 수신이 멈췄다는 표시가 판매 화면 상단에 나온다

## 6. 지표
| 지표 | 정의 | 현재 | 목표 |
| --- | --- | --- | --- |
| 픽업 주문 입력 오류 | 매장당 월 오류 건수 | 6건 | 1건 이하 |
| 주문 접수 소요 시간 | 주문 수신 ~ 접수 P50 | 95초 | 30초 |
| 미접수 자동 취소율 | 10분 내 미접수 자동 취소 / 픽업 주문 | 2.3% | 0.5% |
